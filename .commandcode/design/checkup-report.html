// PRIORITY ISSUES
P0 — CRITICAL

No Visible Focus Indicators

Search input (search-bar.tsx:544), compose recipient inputs (compose-modal.tsx:377), and markdown textarea (markdown-editor.tsx:194) all use bare outline-none with no replacement. Keyboard users tabbing through the interface get zero feedback about which element is focused. WCAG 2.4.7 violation — Focus Visible.

FIX: Replace all bare outline-none with focus-visible:ring-2 focus-visible:ring-blue-500 focus-visible:ring-offset-2 focus-visible:outline-none. Apply to every interactive element: buttons, inputs, textareas, and clickable rows.
P1 — HIGH

iOS Safari Input Zoom

All form elements use text-sm (14px) or smaller: search input, Compose To/Cc/Bcc/Subject fields, reply composer fields, markdown textarea (13px text-[13px]), AI draft input, and filter popover fields. iOS Safari auto-zooms when any form element below 16px receives focus, breaking the layout. Do not use maximum-scale=1 to suppress zoom — that disables pinch-to-zoom.

FIX: Add max-sm:text-base to all inputs and textareas. On screens under 640px, bump to 16px. The markdown textarea needs text-base instead of text-[13px] on mobile.
P2 — MEDIUM

Widespread Sub-12px Text

18+ instances of text-[11px] across thread list snippets, dates, filter labels, and metadata. The unread badge uses text-[10px]. On high-DPI screens this renders at ~8.5 physical pixels — below the threshold where letterforms remain distinguishable and readable.

FIX: Bump body-like text to text-xs (12px) minimum. text-[10px] is acceptable only for the unread badge (decorative, high-contrast white on accent). Otherwise, nothing below 12px.
